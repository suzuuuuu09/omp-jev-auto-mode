## 確認画面の変更と検証

`combine()` は拒否された確認必須条件と未解決の必須条件の理由をすべて集め、復元不能な損失を先頭に表示する。`decidingRule` は従来の選択を維持し、表示の順序だけを変更した。UIは複数行の理由と渡された追加理由をすべて表示する。コマンド全文・対象・秘密情報のマスキング、Yes/Noの操作は維持した。`src/extension.ts` は既にrationaleと追加理由を渡しているため変更不要だった。

変更前のHEADと変更後の `combine()` を、全9条件について0・0.5・1の19,683通りで比較し、rationale以外の出力が一致した。`bun run check` は型チェックと40テストが成功、`git diff --check` も成功した。通常テストには、複合理由・損失の優先表示・長い複数行コマンド・マスキング・形式ごとのマスキング・不足した祖先の拒否を含む。OMP実画面での描画と拡張の再配置は未検証。

- B：発言を `{order, text}` の配列にし、最新発言の順序を明示。

## 実セッションの再構成

元のローカルJSONLの親IDをたどり、各判定時点のユーザー発言だけを抽出した。助手発言・ツール出力・注入されたユーザーメッセージは含めない。読み込んだ私的本文と実際のDM識別子はメモリ上だけで扱い、fixture・結果ログには保存していない。APIへ送る前の秘密情報マスキングを全方式で維持している。

- ヘルプ拒否時はユーザー発言4件、抽出文字列95文字。最新の明示的なDM確認依頼も保持されていた。
- 間接的な発言後の閲覧拒否時は、全17発言のうち直近12件、抽出文字列258文字。最新発言は保持されていたが、それ以前の明示的なDM確認依頼は12件の窓外だった。
- 前回の単独fixtureは最新発言1件、架空のDM識別子、評価用の固定context、意図1質問。実際の記録とは履歴・コマンドの具体値・質問セットが異なる。
- 元の送信state、設定、質問本文を含むリクエスト全体は保存されていない。したがって当時の完全な再送ではない。特に元のcwd・Git判定・保護パス・policyの内容は確定できず、既存評価ツールの固定contextを全方式で共有した。
- コマンドは判定記録のsummaryから取得した。この2件は要約の上限より短いが、元のtool-call入力との完全一致を保証する送信ログはない。

## 再実行と残る課題

既存の比較ツールを拡張した。通常のテストはAPIを呼ばない。`--dry-run` は必要回数の算出と入力検証だけを行い、キーも読み込まない。

```sh
bun run test/intent-evaluation.ts --representations --dry-run
TYPESAFE_DEFAULT_MODEL=jev-1.13.0 bun run test/intent-evaluation.ts --representations
bun run test/intent-evaluation.ts --session "$OMP_JEV_SESSION" --dry-run
TYPESAFE_DEFAULT_MODEL=jev-1.13.0 bun run test/intent-evaluation.ts --session "$OMP_JEV_SESSION"
```

`OMP_JEV_SESSION` には利用者が元のローカルセッションのパスを指定する。元ファイルがない場合、実セッションの私的本文を結果ファイルから復元することはできない。足りない祖先・条件定義・切り詰めにより発言境界を再構成できない場合は停止し、推測で補わない。

測定値は[公開fixtureの結果](fixtures/intent-context-evaluation-results.jsonl)と[内容を除いた実セッションの結果](fixtures/intent-session-evaluation-results.jsonl)に保存した。終了済み依頼の誤成立、ヘルプ・環境確認の低スコアは残る。次の比較候補は、発言形式を固定したうえで、準備操作と依頼終了の扱いを質問文に明示する方法。今回の形式変更と同時には採用しない。
